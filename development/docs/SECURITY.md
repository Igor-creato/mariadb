## Reporting a Vulnerability

Если вы обнаружили уязвимость безопасности в Cashback Plugin, пожалуйста, сообщите нам об этом ответственно.

### Как сообщить

**НЕ создавайте публичные issue для уязвимостей безопасности!**

Вместо этого:

1. Отправьте email на: security@example.com
2. Укажите:
   - Описание уязвимости
   - Шаги для воспроизведения
   - Потенциальное воздействие
   - Предлагаемое решение (если есть)

### Что происходит дальше

1. **Подтверждение** (24 часа): Мы подтвердим получение вашего отчета
2. **Анализ** (7 дней): Мы проанализируем проблему и оценим риски
3. **Исправление** (30 дней): Мы разработаем и протестируем исправление
4. **Выпуск** (после исправления): Мы выпустим патч и публично раскроем информацию

### Благодарности

Мы благодарны исследователям безопасности, которые ответственно раскрывают уязвимости. Мы упомянем вас в:

## Реализованные меры безопасности

### Защита от CSRF

- Nonce-проверка для всех AJAX запросов
- Проверка прав доступа (capabilities)
- Валидация источника запросов

### Защита от XSS

- Экранирование всех выходных данных (`esc_html`, `esc_attr`, `esc_url`, `esc_js`)
- Использование `wp_kses_post` для HTML контента
- Санитизация пользовательского ввода

### Защита от SQL-инъекций

- Использование prepared statements (`$wpdb->prepare()`)
- Валидация префиксов таблиц
- Экранирование имен таблиц в DDL запросах
- Параметризованные запросы

### Дополнительные меры

- Rate limiting для предотвращения спама (5 тикетов/час, 20 ответов/час)
- Валидация длины входных данных
- Проверка типов данных (`declare(strict_types=1)`)
- Идемпотентность операций (защита от дублирования)
- Транзакции для критических операций

## Best Practices для пользователей

1. **Всегда обновляйте плагин** до последней версии
2. **Используйте сильные пароли** для всех учетных записей
3. **Включите двухфакторную аутентификацию** (если доступна)
4. **Регулярно делайте резервные копии** базы данных
5. **Ограничьте доступ** к админ-панели WordPress
6. **Используйте SSL/TLS** для шифрования трафика
7. **Следите за логами** на предмет подозрительной активности

## Security Checklist для разработчиков

Перед каждым релизом проверяем:

- [ ] Все входные данные валидируются
- [ ] Все выходные данные экранируются
- [ ] Используются prepared statements
- [ ] Проверяются права доступа
- [ ] Используются nonces
- [ ] Нет жестко закодированных учетных данных
- [ ] Нет SQL-инъекций в триггерах/событиях
- [ ] PHPStan проходит без критических ошибок
- [ ] PHPCS проходит согласно WordPress Coding Standards

## Известные ограничения

1. **MySQL Events**: Могут быть отключены на некоторых хостингах
2. **Триггеры**: Требуют права TRIGGER на уровне БД
3. **Prepared Statements**: Не поддерживаются для DDL команд (CREATE TRIGGER, CREATE EVENT)

## Версии зависимостей

Минимальные версии для безопасности:

- PHP 7.4+ (рекомендуется 8.1+)
- WordPress 6.2+ (обязательно для wpdb::prepare %i placeholder)
- WooCommerce 5.0+
- MySQL 5.7+ / MariaDB 10.2+
