# Changelog: Функционал возврата средств при failed-статусе

**Дата:** 2026-02-05  
**Версия:** 1.1.0  
**Автор:** Development Team

## 📋 Описание изменений

Добавлен функционал автоматического возврата средств из `pending_balance` в `available_balance` при установке статуса выплаты в `failed` (Возврат в доступный баланс).

## ✨ Новые возможности

### 1. Автоматический возврат средств

- При изменении статуса заявки на выплату на `failed` средства автоматически возвращаются из `pending_balance` в `available_balance`
- Возврат выполняется в рамках безопасной транзакции с защитой от дублирования
- Запись остается в таблице `wp_cashback_payout_requests` и отображается в кабинете клиента и администратора

### 2. Защита от дублирования

#### База данных:

- Добавлена колонка `refunded_at` (datetime NULL) - время возврата средств
- Добавлен индекс `idx_refunded` для быстрого поиска возвращенных заявок
- Поле `refunded_at` устанавливается только один раз при первом возврате средств

#### Код приложения:

- Проверка на существующее значение `refunded_at` перед выполнением возврата
- Использование оптимистичной блокировки через поле `version` в таблице балансов
- Блокировка строки баланса через `FOR UPDATE` в транзакции

### 3. Защита финального статуса

Статус `failed` является финальным и не может быть изменен:

#### Триггеры базы данных:

- `wp_tr_prevent_delete_failed_payout` - запрещает удаление заявок со статусом `failed`
- `wp_tr_prevent_update_failed_payout` - запрещает изменение заявок со статусом `failed`

#### Логика приложения:

- Проверка старого статуса перед выполнением операций
- Возврат средств выполняется только при переходе из другого статуса в `failed`

## 🗄️ Изменения в базе данных

### Таблица `wp_cashback_payout_requests`

```sql
-- Новая колонка
`refunded_at` datetime DEFAULT NULL COMMENT 'Время возврата средств после failed-статуса'

-- Новый индекс
KEY `idx_refunded` (`refunded_at`)
```

### Новые триггеры

```sql
-- Защита от удаления
CREATE TRIGGER `wp_tr_prevent_delete_failed_payout`
BEFORE DELETE ON `wp_cashback_payout_requests`
FOR EACH ROW
BEGIN
    IF OLD.status = 'failed' THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Удаление запрещено: заявка со статусом failed не может быть удалена.';
    END IF;
END;

-- Защита от изменения
CREATE TRIGGER `wp_tr_prevent_update_failed_payout`
BEFORE UPDATE ON `wp_cashback_payout_requests`
FOR EACH ROW
BEGIN
    IF OLD.status = 'failed' THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Изменение запрещено: заявка со статусом failed не может быть изменена.';
    END IF;
END;
```

## 💻 Изменения в коде

### Файл: `mariadb.php`

#### Обновлена структура таблицы `cashback_payout_requests`:

- Добавлена колонка `refunded_at`
- Добавлен индекс `idx_refunded`

#### Обновлен метод `create_triggers()`:

- Добавлено удаление старых триггеров `wp_tr_prevent_delete_failed_payout` и `wp_tr_prevent_update_failed_payout`
- Добавлено создание новых триггеров для защиты failed-статуса

### Файл: `admin/payouts.php`

#### Новый метод `update_user_balance_on_failed()`:

```php
/**
 * Обновление баланса пользователя при изменении статуса выплаты на "failed"
 * Возвращает средства из pending_balance в available_balance
 *
 * @param int $payout_id ID запроса на выплату
 * @return bool Результат операции
 */
private function update_user_balance_on_failed(int $payout_id): bool
```

**Особенности реализации:**

- Проверка на повторный возврат через `refunded_at`
- Блокировка строки баланса `FOR UPDATE` в транзакции
- Оптимистичная блокировка через поле `version`
- Полный откат транзакции при любой ошибке
- Детальное логирование всех операций

#### Обновлен метод `handle_update_payout_request()`:

```php
// Если статус меняется с любого другого на 'failed', возвращаем средства в available_balance
if ($old_status !== 'failed' && $status === 'failed') {
    $refund_result = $this->update_user_balance_on_failed($payout_id);

    if (!$refund_result) {
        wp_send_json_error(['message' => __('Ошибка при возврате средств в баланс.', 'cashback-plugin')]);
        return;
    }
}
```

## 🔐 Безопасность

### Защита от конкурентных операций:

1. **Транзакции** - все операции выполняются атомарно
2. **FOR UPDATE** - блокировка строки баланса на время транзакции
3. **Optimistic locking** - проверка версии записи перед обновлением
4. **Проверка refunded_at** - предотвращение повторного возврата

### Защита от некорректных данных:

1. **Проверка наличия средств** - возврат не выполнится если в pending_balance недостаточно средств
2. **Подготовленные запросы** - все SQL-запросы используют `$wpdb->prepare()`
3. **Проверка прав** - `current_user_can('manage_options')`
4. **Nonce validation** - защита AJAX-запросов

## 📊 Процесс возврата средств

```
Администратор меняет статус на "failed"
    ↓
Проверка: старый статус != "failed"
    ↓
Начало транзакции
    ↓
Получение данных заявки (user_id, amount, refunded_at)
    ↓
Проверка: refunded_at пуст? (защита от дублирования)
    ↓
Блокировка строки баланса (FOR UPDATE)
    ↓
Проверка: pending_balance >= amount?
    ↓
Обновление балансов с проверкой version
    ↓
Установка refunded_at = NOW()
    ↓
Commit транзакции
    ↓
Логирование успешной операции
```

## 🧪 Тестирование

### Сценарии для тестирования:

1. **Базовый сценарий:**
   - Создать заявку на выплату со статусом `waiting`
   - Изменить статус на `failed`
   - Проверить что средства вернулись в `available_balance`
   - Проверить что `refunded_at` установлен

2. **Защита от дублирования:**
   - Попытаться повторно изменить статус `failed` (должно быть запрещено триггером)
   - Проверить код на попытку повторного возврата средств

3. **Проверка транзакций:**
   - Эмулировать ошибку базы данных во время возврата
   - Проверить что баланс не изменился (откат транзакции)

4. **Конкурентный доступ:**
   - Запустить два параллельных запроса на возврат средств
   - Проверить что средства возвращены только один раз

## ⚠️ Известные ограничения

1. **Финальность статуса:** После установки статуса `failed` его НЕЛЬЗЯ изменить. Если это было ошибкой, потребуется создать новую заявку на выплату.

2. **Требования к балансу:** Для возврата средств в `pending_balance` должно быть достаточно средств (>= сумма заявки).

3. **Совместимость:** Изменения требуют MariaDB 11.5+ для корректной работы триггеров.
